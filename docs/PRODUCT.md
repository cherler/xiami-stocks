# 虾米看股：初始产品文档

| 项目 | 内容 |
|---|---|
| 产品名称 | 虾米看股 |
| 代码名称 | `xiamimate-stock-lab` |
| 文档版本 | 0.2 |
| 日期 | 2026-08-03 |
| 当前阶段 | 阶段 1：核心研究档案开发中 |
| 目标市场 | 中国 A 股，后续可扩展港股 |

## 1. 产品结论

虾米看股不是一套预测涨跌或自动交易的系统，而是面向个人价值投资者的**长期研究与决策记忆系统**。

它要把分散在行情软件、公告、新闻、财报、产业链资料和个人笔记里的内容，持续归档到公司实体之下，并让每次判断都保留“当时看到了什么、依据是什么、后来发生了什么”。

产品的首要问题不是“今天涨了多少”，而是：

1. 我的投资逻辑是否仍然成立？
2. 最近出现了哪些可能证实或推翻它的新事实？
3. 当前价格相对企业质量和历史估值，是否进入值得进一步研究的区间？

## 2. 用户与使用场景

### 2.1 核心用户

- 以价值投资和中长期持有为主的个人投资者；
- 持有或长期观察约 10–50 家 A 股公司；
- 每日只需低频浏览事件，每周或每季度集中研究；
- 愿意亲自做最终判断，希望 AI 帮助整理证据而不是替自己下单。

### 2.2 核心场景

- 开盘前或收盘后，用 5 分钟了解自选公司出现了什么重要变化；
- 财报发布后，更新关键指标并重新检查投资逻辑；
- 估值明显变化时，结合历史区间而不是单看绝对 PE/PB；
- 买入、加仓、减仓或清仓时，记录理由、证据和反证条件；
- 每月或每季度复盘：哪些判断被事实验证，哪些是信息遗漏或认知错误；
- 研究某家公司时，沿产业链、竞争对手和上下游关系展开，而不是只读孤立新闻。

## 3. 产品原则

### 3.1 事实、推断、观点分层

公告与财务原文属于事实；从事实得出的影响判断属于推断；用户最终是否认可属于个人观点。三者必须在界面和数据结构中分开。

### 3.2 证据可追溯

任何 AI 摘要和判断都必须保存来源、原文时间、抓取时间和引用片段。没有来源的内容只能进入“待核验”，不能写入正式投资逻辑。

### 3.3 逻辑先于价格

首页优先展示逻辑状态、待复核事件、财务变化和组合风险；实时价格、分时图和涨跌榜不占据核心位置。

### 3.4 保留当时的判断

研究笔记、逻辑版本和交易理由采用追加版本，不静默覆盖历史。用户需要能够回到任意一次交易发生时，查看当时的信息环境。

### 3.5 AI 只做研究助手

AI 可以抽取、归纳、对比和提示矛盾；最终的逻辑状态、交易动作和证据采纳由用户确认。

| | **不做交易流水、不做交割单读图**：那是在跟券商 APP 抢同一份活，而券商那边永远更准、更新、且不用你动手（2026-09-23 定） | |

这些项目只作为产品和实现参考。首版不直接拼接仓库，所有外部代码在引入前必须单独核对许可证、依赖和数据授权。

### 4.2 明确不做

- 自动交易、券商下单和账户托管；
- 交易流水账与交割单识别（2026-09-23 删除，理由见上表「持仓」一行）。

  > **「计划内 / 计划外交易」没有跟着一起删。** 它原来查账本里的买入流水，
  > 而持仓改成只记两个数之后账本里再也不会有买入 —— 那个指标会**永久归零
  > 而且不报错**，页面上看起来只是「你还没交易过」。
  >
  > 所以它换了数据源：成交登记挪到决策卡上（`decision_fills`），
  > 在你真正下单的那一刻记一次实际成交价，而不是事后回账本补一笔流水。
  > **登记不改持仓**——持仓仍然只由你自己填的那两个数决定。
  >
  > 删一个功能时，先问它有没有在给别的东西供数。
- 短线荐股、涨停监控、尾盘选股和热点追涨；
- 精确买卖点、目标价、止盈止损建议；
- 分时成交、盘口、毫秒级或秒级行情；
- 技术指标大全、缠论、波浪和复杂量化回测；

  > **「做 T 回测」不属于这一条，边界在这里划清楚。**
  >
  > 这一条禁的是**选股策略回测**：在全市场里回头挑股票。那种回测的数字
  > 必然比真实情况好看——幸存者偏差、停牌、退市、前复权口径，每一样都往上抬，
  > 而一个好看的回测最容易让人下重注。
  >
  > 「做 T 回测」问的是另一件事：**一只已经在你手上的股票，它自己的日线上，
  > 那条"一天涨一天跌"的规律成不成立，成立的话扣完成本还剩多少。**
  > 没有挑股票的余地，也就没有可以作弊的余地。它的默认结论往往是
  > 「做不得」——而那正是它存在的理由：把「我没做 T 是不是少赚了」
  > 从一种感觉变成一个能被验算的数。
  >
  > 它仍然不做的事写在 `swing.py` 的开头：不给买卖点、不做分时、不调参寻优。
- 用单一综合分数代替用户判断；
- 无来源的 AI 结论。

## 6. 首屏定义：决策总览

首屏的单一任务是：**让用户快速知道哪些长期判断需要重新检查。**

### 6.1 投资逻辑账本

每家公司维护 1–5 条可验证的逻辑，每条逻辑包含：

- 一句话主张；
- 支持证据与来源；
- 反证条件；
- 最后复核时间；
- 下次复核触发条件；
- 用户确认的状态。

状态不是 AI 评分，而是用户确认后的枚举：

| 状态 | 含义 |
|---|---|
| 成立 | 现有事实继续支持原逻辑 |
| 待观察 | 证据不足或验证窗口尚未到来 |
| 受挑战 | 已出现重要反证，但尚不足以推翻 |
| 已破坏 | 关键反证条件已经发生 |

### 6.2 事件收件箱

公告、财报和新闻先进入事件收件箱。系统完成去重、实体匹配和初步分类后，用户决定：

- 忽略；
- 归档为普通事件；
- 关联到某条投资逻辑；
- 标为反证并触发复核；
- 创建研究任务。

### 6.3 市场云图

首版仅提供行业层级、全 A/主要指数范围和日/周/月切换。它用于理解市场结构，不提供追涨入口；点击行业后进入行业公司列表和长期指标对比。

## 7. 公司档案

### 7.1 公司概览

- 公司名称、代码、行业、主营业务和关键产品；
- 最新数据日期和各数据源健康状态；
- 持仓情况和成本信息；
- 最近一次完整复核结论。

### 7.2 财务趋势

首版优先支持以下指标，并保留报告期、TTM、币种和原始字段口径：

- 营收及增速；
- 归母净利润及增速；
- 毛利率、净利率和 ROE；
- 经营现金流与净利润匹配；
- 有息负债、资产负债率；
- 应收、存货和资本开支变化。

当前已实现第一层：按报告期同步营收、归母净利润、经营现金流、总资产、总负债、资产负债率，并展示年度 ROE 估算。图表优先使用年度报告；年度数据不足时会明确改用最近报告期，避免把单季数值当作全年数值。毛利率、TTM、应收、存货、资本开支和有息负债仍属后续范围。

### 7.3 估值

- PE-TTM、PB、股息率和自由现金流收益率；
- 近 3/5/10 年历史区间与分位；
- 负利润、周期股和一次性损益等异常口径提示；
- 估值变化与盈利变化分开呈现。

估值只作为进一步研究的触发器，不直接输出“便宜”或“应该买入”。

### 7.4 历史判断

按时间轴保留逻辑版本、研究报告、重要事件和交易记录，支持回看“当时版本”，避免事后修改理由。

## 8. AI 分析规范

### 8.1 允许输出

- 事件事实摘要；
- 与历史数据或上一报告期的变化对比；
- 可能影响的投资逻辑及影响方向；
- 支持证据、反证和仍缺失的信息；
- 建议用户继续核验的问题；
- 带来源引用的阶段研究报告。

### 8.2 禁止输出

- 确定性的买入、卖出、目标价和收益承诺；
- 把新闻标题或搜索摘要当作已核验事实；
- 隐藏冲突证据；
- 用技术指标生成短线操作建议；
- 在没有数据日期和来源时给出结论。

### 8.3 报告固定结构

```text
本次变化
事实与来源
对既有投资逻辑的影响
支持证据
反证与风险
尚缺信息
需要用户确认的事项
```

## 9. 核心数据模型

| 实体 | 关键字段 |
|---|---|
| Company | 证券代码、名称、行业、交易所、别名、主营摘要 |
| Watchlist | 名称、类型、排序规则 |
| WatchlistItem | 公司、关注理由、加入时间、复核日期 |
| Thesis | 公司、主张、反证条件、状态、版本、确认人、确认时间 |
| Evidence | 来源、原文时间、抓取时间、摘要、引用片段、可信级别 |
| ThesisEvidence | 逻辑、证据、支持/反对/中性、影响说明 |
| Event | 公司、类型、重要性、事件时间、去重键、核验状态 |
| FinancialMetric | 公司、报告期、指标、数值、口径、来源 |
| ValuationSnapshot | 公司、交易日、估值指标、历史分位、口径 |
| IndustryRelation | 主体、关系类型、目标、证据、有效期 |
| PortfolioPosition | 公司、数量、成本、组合、更新时间 |
| TradeJournal | 动作、数量、价格、理由、关联逻辑、发生时间 |
| ResearchReport | 公司、报告类型、数据截止日、正文、引用、模型版本 |

所有可更新的研究实体应包含 `created_at`、`updated_at`；逻辑、报告和交易理由还应保留不可变版本。

## 10. 数据分层与接口边界

```text
外部来源
  行情 / 财报 / 公告 / 新闻 / RSS / 手工录入
          ↓
采集适配层
  限流、重试、原始响应留存、来源健康检查
          ↓
标准化层
  证券标识、财报口径、时间、去重、实体匹配
          ↓
证据与领域层
  公司、逻辑、事件、财务、估值、产业链、交易账本
          ↓
应用层
  总览、公司档案、报告、提醒、搜索
```

### 10.1 数据新鲜度目标

| 数据 | 首版目标 |
|---|---|
| 日线行情与估值快照 | 每个交易日收盘后更新 |
| 公告 | 交易时段每 30 分钟，非交易时段每 2 小时 |
| 新闻与 RSS | 每 1–2 小时 |
| 财报指标 | 报告发布后 24 小时内完成标准化 |
| 产业链关系 | 按证据事件触发或每季度复核 |

首版允许手动触发刷新。数据过期时必须直接显示截止日期，不用旧数据伪装实时。

## 11. MVP 范围与验收标准

### 11.1 MVP 功能

1. 建立自选股分组并维护公司基础档案；
2. 为公司创建、更新和版本化投资逻辑；
3. 录入公告/新闻事件并关联逻辑；
4. 查看基础财务趋势和估值历史分位；
5. 记录持仓和买卖决策理由；
6. 在总览查看待复核逻辑、重要事件和组合暴露；
7. 生成一份带来源的阶段研究报告；
8. 显示每类数据的更新时间和健康状态。

### 11.2 MVP 验收

- 用户能在 5 分钟内找到本周最需要复核的 3 家公司及原因；
- 任意 AI 结论都能回到原始来源或被明确标为待核验；
- 任意一笔交易都能关联到当时版本的投资逻辑；
- 财务指标不会混用年度、单季度和 TTM 口径；
- 页面没有自动交易、目标价或短线买卖信号；
- 数据源失效或过期时，页面明确提示而不是静默展示；
- 桌面大屏和手机宽度均能完成核心阅读与复核操作。

## 13. 技术起点

| 层 | 初始选择 | 原因 |
|---|---|---|
| Web | React + TypeScript + Vite + ECharts | 适合数据看板，开发和部署简单 |
| API | FastAPI + Pydantic | 数据任务与 Python 生态衔接自然 |
| 存储 | SQLite 起步，预留 PostgreSQL | 个人使用部署轻，后续迁移清晰 |
| 调度 | 首版手动触发，后续 APScheduler/独立 worker | 避免过早引入复杂队列 |
| 原始数据 | 文件/对象存储留档 | 支持追溯来源和重新标准化 |
| 部署 | 本地优先，后续 Docker Compose | 先验证个人工作流 |

## 14. 主要风险与控制

| 风险 | 控制方式 |
|---|---|
| 免费数据源变更、限流或失效 | 适配器隔离、多源降级、健康检查、手工导入 |
| 财报口径混乱 | 存储报告期与口径，原始值留档，建立指标字典 |
| 新闻误匹配公司 | 别名库 + 规则匹配 + 人工确认，低置信度不自动入档 |
| AI 幻觉 | 强制引用、事实/推断分层、用户确认后改变逻辑状态 |
| 研究记录事后被改写 | 逻辑和交易理由版本化，保留时间戳 |
| 项目范围膨胀为量化平台 | 以“不做清单”和 MVP 验收持续约束 |
| 外部项目许可证不明确 | 先参考产品思路，引入代码前逐仓审计并记录来源 |
| 投资信息合规 | 首版保持个人自用，不提供荐股和收益承诺 |

## 15. 成功指标

首版不以日活或交易次数为目标，优先观察：

- 重要公告/财报被纳入研究档案的完整率；
- 事件进入系统后到用户完成复核的时间；
- 有明确证据和反证条件的投资逻辑占比；
- 有关联逻辑与理由的交易记录占比；
- AI 报告中可追溯陈述的比例；
- 数据过期或采集失败被正确暴露的比例；
- 每季度完成复核的持仓公司占比。

## 16. 下一步产品决策

进入阶段 1 前，需要逐项确定：

1. 首批真实数据源及使用条款；
2. 个人持仓数据采用手工录入、CSV 导入还是券商导出文件；
3. 首批 10–20 家种子公司的指标模板；
4. 投资逻辑状态由谁确认，以及是否允许自动提醒但禁止自动修改；
5. 原始公告和财报文件的本地存储期限；
6. 是否从第一版就支持港股通公司。
