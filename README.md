- 价值候选清单：四套有出处的预置策略，不设条件也能出候选，每家附全部入选依据；
- 全市场数据底座：全 A 与四个主要指数的行情、估值与财务核心指标，每日调度更新；
- 行业对照：按证监会行业分类比较研究池内公司的估值分位、ROE、毛利率与负债率；

## 快速开始

### 前端

```bash
npm install
npm run dev
```

用户入口统一为 `http://127.0.0.1:3000/stocks`。不要直接访问 Vite 内部端口 `5217`：它只供主站本地网关转发和开发热更新使用，不是虾米看股的稳定入口。前端依赖本地 API；若 API 未启动，会明确提示连接失败而不会展示伪造数据。

### API

需要 Python 3.11 或更高版本。本机可直接使用已安装的 Python 3.12：

```bash
/opt/miniconda3/bin/python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
uvicorn stock_decision.main:app --reload --app-dir apps/api --port 8108
```

默认访问 `http://localhost:8108`，接口文档位于 `http://localhost:8108/docs`。

首次启动 API 会在 `var/stock_decision.db` 建立本地数据库。若档案为空，系统通过 [StockSDK](https://stock-sdk.linkdiary.cn/guide/introduction) 同步 3 只真实 A 股作为起始研究池：代码、名称、价格、涨跌幅、PE、PB、52 周区间、时间和来源均来自 SDK，不使用虚构行情或公司资料。这个数据库仅保存在本机，已在版本控制中忽略。

在总览点击“同步实时行情”，或调用以下接口，可以刷新所有已关注公司的行情快照：

```bash
curl -X POST http://localhost:8108/api/v1/market/refresh
```

同步由服务端调用 `stock-sdk`，前端只读取本地快照。StockSDK 需要 Node.js 18+；本项目已将它锁定为前端工作区的依赖。

财务数据由服务端通过 [AKShare 的新浪财经定期报告接口](https://akshare.akfamily.xyz/data/stock/stock.html) 同步，读取利润表、现金流量表和资产负债表的原始报告期数值。年报 ROE 是以归母净利润除以平均归母权益得到的估算值，只在年度报告显示；非年报不会被伪装成年度 ROE。可在公司档案点击“同步财务数据”，或调用：

```bash
curl -X POST http://localhost:8108/api/v1/companies/1/financials/refresh
```

财务指标里的派生值都写明口径：毛利率取 (营收 − 营业成本) / 营收，现金含量取 经营现金流 / 归母净利润，自由现金流按 经营现金流 − 购建长期资产支付的现金 估算，周转天数按报告期天数折算；TTM 为"本期累计 + 上年年报 − 上年同期累计"。非年报不会与年报直接比较金额和周转天数，来源没有的科目显示为空而不是 0，并在提示区列出缺口。

行业、投资逻辑、公告和证据字段不会用示例内容填充；未接入时会明确显示为空或待补充。

新建公司时，在“公司档案”输入 6 位 A 股代码并点击“校验代码”。系统只会在 StockSDK 返回真实名称和行情后创建档案；行业、研究缘起和投资逻辑依然由你补充与确认。也可用以下接口进行校验：

```bash
curl 'http://localhost:8108/api/v1/quotes/resolve?symbol=600519'
curl http://localhost:8108/api/v1/data-providers
```

## 公司简况

公司档案顶部的“公司简况”需要手动同步一次。数据来自巨潮资讯（公司资料、公告披露）、同花顺（分红方案）和新浪（限售解禁）：

```bash
curl -X POST http://localhost:8108/api/v1/companies/1/profile/refresh
```

其中股息率是按最近一次已实施的分红方案与最新价估算的派生值，页面上已标明口径；股本、注册资金、募集资金以“亿股/亿元”换算展示。任一子接口取不到数据时，页面会列出缺失的板块，不用占位内容填充。

## 持仓与交易账本

在“持仓账本”页或公司档案的“持仓与决策账本”区录入交易。账本只保存你手工录入的记录，不连接券商账户，也不会自动下单或给出买卖建议：

```bash
curl http://localhost:8108/api/v1/portfolios
curl -X POST http://localhost:8108/api/v1/portfolios/1/trades \
  -H 'Content-Type: application/json' \
  -d '{"company_id":1,"side":"buy","trade_date":"2026-01-08","shares":200,"price":1420.5,"fee":42.6,"rationale":"记录当时依据的事实","review_due":"2026-09-30"}'
```

口径：成本为移动加权平均，买入费用计入成本，卖出费用冲减已实现盈亏；卖出股数超过持仓会被拒绝。每笔交易会留存下单当时关联的投资逻辑原文，之后逻辑被修改也能回看当初的判断。目前尚未处理分红、送转和拆并股对成本的调整。

## 研究任务

在"价值候选"页点"存成研究任务"，这份清单就固化成 `http://127.0.0.1:3000/stocks/tasks` 里的一条任务：它记着当初用的策略与条件、那份数据的样本量与截止日，以及每家的入选依据。之后逐家标记"待看 / 已建档 / 已排除"并写下结论，进度实时可见；看完写一句整体结论结束任务。

```bash
curl -X POST http://localhost:8108/api/v1/tasks -H 'Content-Type: application/json' \
  -d '{"title":"2026Q2 质量线复筛","strategy_key":"quality_steady","limit":20}'
curl http://localhost:8108/api/v1/tasks
```

已经在研究池里的公司会自动标为已建档。

## 市场云图

`http://127.0.0.1:3000/stocks/heatmap` 把全 A 或某个主要指数按行业铺成色块：面积代表规模（优先总市值，行情源没给市值时退回公司家数并标明），颜色是所选指标。点击行业下钻到行业内公司，点击公司可直接建档或打开已有档案。

```bash
curl 'http://localhost:8108/api/v1/heatmap?scope=all&metric=roe'
curl 'http://localhost:8108/api/v1/heatmap?scope=index:000300&metric=gross_margin'
curl 'http://localhost:8108/api/v1/heatmap?scope=industry:半导体&metric=roe'
```

行业层用成员**中位数**而不是平均值——一家亏损公司的负 ROE 会把整个行业的平均值拉到没有意义。比率类指标用单色阶，深浅只表示数值高低、不表示好坏；同比与当日涨跌用红涨绿跌的双向色阶。云图只描述市场结构与指标分布，不排序推荐，也没有短线追涨入口。

## 价值候选清单

`http://127.0.0.1:3000/stocks/screener` 不需要先设条件：选一套预置策略就出一份候选，不满意换一套。

| 策略 | 出处 | 已知偏差（页面上会完整列出） |
|---|---|---|
| 低估防御型 | 格雷厄姆防御型估值标准 | 周期股在利润顶点时 PE 最低，会在周期顶部推荐 |
| 质量稳健型 | 高 ROE + 高毛利 + 现金覆盖 | 偏好轻资产；识别不出靠杠杆撑起的 ROE |
| 经营改善型 | 借鉴 Piotroski F-Score 的变化方向思路（简化版） | 只看方向不看起点；单期高增长常来自低基数 |
| 质量成长型 | GARP | PEG 用单期增速，对增长持续性无能为力 |
| 股息现金流型 | 股息率与派息可持续性 | 待接入股息率数据后开放 |

每套策略声明它依赖哪些字段；底座里字段完整度不足时该策略自动停用并说明缺什么（例如行情降级导致 PE/PB 缺失时，低估型与成长型不可用）。候选按"多策略交集优先"排序，每家可展开看到全部入选依据的实际值。

```bash
curl http://localhost:8108/api/v1/screen/strategies
curl -X POST 'http://localhost:8108/api/v1/screen/run?strategy=quality_steady&limit=20'
curl http://localhost:8108/api/v1/screen/runs
```

点"调整条件"可以在页面里直接改门槛、加减条件、换排序：先"试跑（不保存）"看命中多少家，满意再"存为我的策略"。每个可选字段都标出口径提示与底座完整度，数据不足的字段会提前提示。预置策略不会被改写，只能复制；复制出来的策略会带上原策略的已知偏差——改了门槛不等于改掉了它的盲区。

规则结果下方的第二步“模型复核”是后台任务：点击后立即返回，模型在服务端运行，切换页面、刷新浏览器都不会清掉进度。完成后结果自动保存，回来会按“策略 + 复核家数”恢复。它与研究任务页的“让模型先看一遍”共用同一套候选初筛评语：结论、支持依据和待核实事项保持一致；模型只回答“值不值得继续花时间”，不回答“该不该买”。

这份清单回答的是"接下来研究哪几家"，不是"该不该买"：不给目标价、不给买卖时点、不给不说明依据的评分。建档后请在公司档案同步财报与公告，再用复核工作台逐条确认。

## 行业与同业对照

同步"公司简况"时，档案里还是"待补充"的行业会用巨潮的证监会分类回填（你自己写过的行业不会被覆盖）。`http://127.0.0.1:3000/stocks/industries` 按行业把研究池里的公司放在一起比较；公司档案的"行情与估值"标签里也有同一张表并高亮当前公司。

```bash
curl http://localhost:8108/api/v1/industries
curl 'http://localhost:8108/api/v1/industries/comparison?industry=电气机械和器材制造业'
```

两条边界写在表格下方：对照范围只是本地研究池里的同行业公司，不是全行业样本；行业口径为证监会分类，比较粗（家电与电池会落在同一类）。缺数据的格子显示"—"并说明原因，不用 0 顶替；分位只说明各自在自身历史中的位置，不能直接当成同业间的贵贱比较。

## 复核工作台

`http://127.0.0.1:3000/stocks/reviews` 回答同一个问题：当初的理由现在还成立吗。

逻辑会在四种情况下进入待复核队列，并写明是哪一种：复核日期到期、关联交易的复核日期到期、上次复核后出现新的反证或高重要度事件、距上次复核超过 90 天。打开后左中右三栏分别是：当初的判断与交易理由、上次复核之后新增的证据与事件、期间的价格与估值分位以及当前持仓盈亏。

结论从"仍然成立 / 受到挑战 / 已被推翻 / 维持观察"中选一个并写下依据，保存后会作为逻辑的新版本追加（旧判断不被覆盖），同时记录当时的价格、PE 分位与盈亏，并把已到期的关联交易复核日期一并推进。

```bash
curl http://localhost:8108/api/v1/reviews/queue
curl http://localhost:8108/api/v1/theses/1/review-context
curl -X POST http://localhost:8108/api/v1/theses/1/reviews \
  -H 'Content-Type: application/json' \
  -d '{"verdict":"challenged","note":"中报确认了反证条件的一半","next_review_date":"2026-11-15"}'
curl http://localhost:8108/api/v1/reviews/attribution
```

## 自动同步

API 启动后会带起一个后台调度器，按数据类型分别同步（默认全部开启，可在"数据状态"页逐个关闭或改间隔）：

| 任务 | 默认间隔 | 说明 |
|---|---|---|
| 实时行情快照 | 30 分钟（仅交易日） | 价格、涨跌幅、PE/PB 与当日估值快照 |
| 前复权日线 | 12 小时（仅交易日） | 区间表现与走势图所依赖的日线 |
| 公司简况与公告 | 1 天 | 公司资料、分红、解禁与公告；新公告进入待核验收件箱 |
| 历史估值序列 | 1 天 | PE(TTM) 与 PB 的近五年序列 |
| 定期报告 | 7 天 | 利润表、现金流量表与资产负债表 |

每个任务独立重试与限流，同一时刻只运行一个；单次运行超过 15 分钟会被判定为未完成并重新排队。任一任务失败不会影响页面读取，页面会显示"仍在用上一次成功的数据"。

```bash
curl http://localhost:8108/api/v1/sync/jobs
curl -X POST http://localhost:8108/api/v1/sync/jobs/quotes/run
curl -X PATCH http://localhost:8108/api/v1/sync/jobs/quotes -H 'Content-Type: application/json' -d '{"enabled":false}'
```

## 估值分位与公告收件箱

公司档案的“估值分位”需要手动同步一次，数据来自百度股市通近五年的市盈率（TTM）与市净率序列，分位在本地计算：

```bash
curl -X POST http://localhost:8108/api/v1/companies/1/valuation/refresh
```

分位 = 样本中不高于当前值的比例，页面会一并给出样本量、样本区间与截止日；样本不足 30 个时不出分位，只说明原因。亏损期的非正 PE 已剔除。分位只描述当前值在历史样本中的位置，不代表贵或便宜。

同步“公司简况”后，公告、分红与解禁会进入“待办复核”页的待核验收件箱，可以按 30/90 天或全部筛选，并一键归档：

```bash
curl 'http://localhost:8108/api/v1/inbox?days=30'
curl -X POST http://localhost:8108/api/v1/inbox/<条目 id>/archive \
  -H 'Content-Type: application/json' \
  -d '{"target":"evidence","polarity":"support","thesis_id":1,"note":"公告里值得记下的关键事实"}'
```

归档会把原文链接与披露日期带进证据或事件；这条公告是否影响投资逻辑，由你判断并确认，系统不会自动认定。

## 收件箱分级（规则 + 模型）

七家公司同步下来就是一千多条公告，其中大部分是股东大会通知、法律意见书这类走流程的文件。分级把它们分成三档：

- **规则先跑**：标题命中分红、解禁、业绩、股权变动、合同、重组、诉讼、监管等实质性词 → 高；命中股东大会流程、独董意见、法律意见书、更正补充、调研记录等程序性词 → 低；回购进展、激励归属这类"既不是新事实也不是纯流程"的 → 中，留给模型。
- **模型接手中间那档**：只处理规则拿不准的条目，走 MiniMax M3（Anthropic 兼容接口），提示词限定它只做分级和客观摘要，**不判断利好利空、不预测股价、不给投资建议**。
- 每条都记下判定依据和判定来源（规则／模型），可以核对，也可以推翻。

配置放在项目根目录的 `.env`（已 gitignore）：

```
MINIMAX_API_KEY=...
MINIMAX_BASE_URL=https://api.minimaxi.com/anthropic
MINIMAX_MODEL=MiniMax-M3
```

没配也能用，规则会独立工作，模型那一档会留在"中"。收件箱默认只显示高和中，"忽略全部程序性"可以一次清掉低档；被忽略的条目仍然留在库里，随时能按状态查回来。

分级只回答「这条是不是实质变化」，不回答「这对你的投资逻辑意味着什么」。

**自动整理**：「自动整理收件箱」一键做完三件事——分级、把实质变化归档为证据、把程序性文件忽略，**只把规则和模型都拿不准的那一档留在收件箱**。这一条同时是每日调度任务（`inbox_tidy`），新公告同步进来后自动走一遍，不用每天手动点。

自动化的边界在这里：分档判断的是"这条是不是实质变化"，不是"这对你意味着什么"。所以归档的证据极性一律留在**中性**，方向由你判断；拿不准的那一档一条都不动。

**按档批量归档**：也可以自己来，不用一条条点。「把实质变化批量归档为证据」会把当前窗口内所有高相关度的公告一次性归入证据档案，来源名称与原文链接都保留。极性一律留在**中性**——这条公告对你的判断是支持还是反证，是真正需要你做的判断，系统不代劳。归档本身只是把它从「还没看过」挪到「已进档案、可追溯」。

## 投资逻辑方法库

给不知道买入理由该怎么写的人用的。十五个方法分四组：找什么、生意好不好、价格贵不贵、怎么少犯错。

每个方法都包含出处（具体到书名与年份）、它逼你回答的核心问题、操作步骤、三段可以直接填的模板（判断／反证条件／复核触发）、适用与不适用的场合，以及它自己的已知盲区。选好方法后可以直接"带着模板去写"，模板会填进对应公司的新建逻辑表单；公司档案的「新建逻辑」表单里也能直接下拉选方法。

**让模型起草**：模板仍然要自己填空，对新手不够。所以表单里还有「让模型按已同步的资料起草」——模型读这家公司档案里**已经同步到的事实**（主营业务、财报科目与同比、估值分位、分红方案、近期公告），产出判断、反证条件和复核触发三段，并列出它用到的每一条事实和它承认自己不知道的部分。

提示词里锁死三件事：只能用传进去的事实（档案里没有的必须写「档案里没有」，不许凭记忆补）、不给目标价与买卖时点、反证条件必须用本站能持续跟踪的字段写清门槛。出来的是草稿——它的意义不是替你判断，而是**先有一个基准**，以后这只股票变化时你才有东西可对照。保存前请逐句核对。

写明出处是因为方法有边界：格雷厄姆的量化标准来自 1940 年代的美国市场，神奇公式是组合层面的方法而不是选单只股票的方法，F-Score 原本是低市净率组合上的筛选层。不知道这些，照抄就是碰运气。

方法库不推荐任何股票，也不判断你写的逻辑对不对；它只提供提问的方式和写作的结构。

## 今日简报（决策总览）

首页顶部由模型生成的一页简报。它回答的问题只有一个：**今天有什么变化，可能影响你已经写下的判断**。
不回答大盘会怎么走、该买什么、该不该加减仓。

上下文全部由代码拼好再交给模型：全市场涨跌家数与中位数、行业当日涨跌首尾、持仓与成本、
已写下的投资逻辑及其反证条件、待复核事项数、最近的高相关公告、研究池里还没写逻辑的公司。

提示词锁死三条：**不预测走势**（明确禁用"或将""有望""预计上涨/回调"）、不补充任何行情新闻宏观观点、
不给目标价与仓位建议。写不出具体公司或数字的段落就不写。

简报会列出「今天可以做的」和「它承认自己不知道的」。实测它自己指出了"中粮资本在投资逻辑里但不在持仓列表中，
无法核对浮动盈亏"——这类缺口比结论本身更有用。按日留档，后台生成，切页面不中断。

## 模型返回的容错解析

模型写中文时经常在值里夹英文双引号（`说明公司"稳定分红"的承诺`），那个引号会把 JSON 字符串截断，
整次调用白跑，用户看到的只是一句看不懂的 `JSONDecodeError`。这不是提示词能百分百约束住的事——
只要有一次没听话就前功尽弃，所以解析这一层自己扛。

`jsonio.loads_lenient` 按顺序修四种实际会遇到的毛病：```json 围栏、尾随逗号、
**值内部的裸双引号**（判据是这个引号后面不是 `: , } ]` 或结尾，那它一定是内容）、字符串里的裸换行。
每一步都只修能确定是格式问题的地方，绝不猜内容；修不好抛出原文开头，方便排查。

六处调用模型的地方（公告分级、候选初筛、资讯匹配、逻辑起草、经营关系线索、简报与研报）全部走这一层。

## 财务算子表

所有比率只在 `operators.py` 里定义一次。**模型永远不碰计算**——它拿到的每个数值都是这里算好的，
连同口径一起给它；它写不出没算过的数，也改不了口径。（这条原则来自 AI4Finance 的 FinRobot：
确定性的财务计算与 LLM 叙述严格分开。）

改之前，同一个毛利率散在四处各算一遍：定期报告的派生指标、候选策略的 `DERIVED`、初筛的行摘要、
起草的事实清单。口径说明也各写各的——同一个 PEG 在候选清单和初筛里可能算得不一样，而且没人会发现。

每个算子声明四件事：

- **inputs**：需要哪些科目。缺一个就返回 None 和缺了什么，**不当成 0**。
- **formula**：口径。同一个"毛利率"不同网站算法不同，口径不跟着数走就没法交叉验证。
- **caveat**：这个比率本身的陷阱。有陷阱的数字比没有数字更危险，因为它看起来可信。
- **fn**：纯函数，只依赖传进来的行。

缺科目和"口径不适用"（分母为零、净利润为负）是两种不同的返回，因为排查时要分得清是取数错还是算子错。

覆盖 18 个比率，分盈利／现金／杠杆／效率／估值五组。数据源自己披露的口径优先——年报的加权 ROE、
披露的资产负债率不会被算子覆盖，算子只补数据源没给的。

**杜邦分解**是算子表带来的新东西：ROE = 净利率 × 总资产周转率 × 权益乘数，回答"高 ROE 是靠赚得多、
转得快，还是靠借得多"——这三条的可持续性完全不同。

## 快照源被挡时的估值推算

东方财富的行情推送服务器（`push2.eastmoney.com`）经常被挡，降级到新浪后只剩价格，
`pe_ttm`／`pb`／`总市值` 全空，五套候选策略里四套因此不可用。

解决办法不是换数据源，而是**从已有的财务底座推算**——业绩报表走的是东财数据中心接口，和被挡的推送服务器不是同一个来源：

- 总股本 = 归母净利润 / 基本每股收益（同一报告期，期间因素相消）
- 总市值 = 现价 × 总股本；市净率 = 现价 / 每股净资产
- 市盈率 = 总市值 / **最近年报**归母净利润——不把当期利润年化，年化对有季节性的生意会系统性失真

候选清单页的「重算估值字段」按钮立刻跑一遍，不用等下一次全量同步；缺年报净利润时它会顺带取回来。
每条记录都写着推算口径，与交易所口径可能有小幅差异（实测贵州茅台 20.67 vs 百度股市通 20.54）。

亏损股（每股收益 ≤ 0）推算不出总股本，留空是对的，不用 0 顶替。

## 候选初筛（模型代读）

研究任务页有「让模型先看一遍」。**它是后台任务**：提交后立刻返回（实测 33 毫秒），模型跑在服务进程里，
和浏览器无关——切页面、刷新、关掉标签都不会打断它，回来还能看到进度。进度写在数据库里，服务重启会把未完成的标成「已中断」并写明原因，不会永远显示运行中。

跑两步：

1. **先补简况**：逐家抓主营业务（巨潮资讯，缺时退回同花顺）、券商研报（东方财富，带机构、评级、日期与 PDF 原文），
   再拼出官方入口——交易所公司页、巨潮公告全文检索、东财行情页、东财研报列表。官方入口是按代码拼的，不发请求，
   所以抓取全挂了你仍然点得进去自己看。
2. **再让模型读**：拿到的是底座里已有的数字（增速、ROE、毛利率、每股经营现金流、市值、PE/PB）加上刚补的主营业务，
   **数字全部由代码取并取整，模型只读不算**——它写不出底座里没有的数值。

结论必须**先用一句话说清这家公司靠什么赚钱**，再谈数字。只有指标没有生意，对不认识这家公司的人没有意义。
资料里没有主营业务时它必须写「档案里没有主营业务描述」，不许凭公司名猜。

研报里的评级是**券商的观点，不是本站的判断**，所以永远连着机构名一起显示。本站自己不产生任何评级。

它只回答一个问题：**这家值不值得你继续花时间**，分三档：值得深入 / 先放着 / 直接排除。不回答该不该买、什么价格买。
异常必须写进「待核实」——低基数造成的极高增速、经营现金流与利润严重背离、ST 标记等。
你改写任何一条结论都会覆盖它，并把来源改成人工。

## 资讯证据

抓公开财经 RSS（东方财富、新浪财经、雪球），去重后对应到已建档的公司。对应分两层：先按公司全称与股票代码精确匹配（零误报、零成本），
剩下的交给模型，而且**模型只能在已建档公司这个封闭集合里选**，选不出就说选不出，选了集合外的 id 一律作废。

和公告收件箱的关键区别：公告是交易所披露的一手事实，资讯是二手转述。所以资讯**不会自动进入任何公司的时间线**——
你打开原文确认过之后，它才会以「媒体转述」标记的来源归档为证据，核验状态是「待核验」，极性中性。

抓不到的源会在结果里点名，不静默跳过：一个长期抓不到的源等于没有这个源。

## 经营关系线索

公司详情页原来的“产业链”已降级为经营关系线索，只列可能的上游供应 / 下游客户 / 同业对手 / 替代方案，不再声称它是一张行业产业链地图。

这是本站**唯一一处依据不是本地档案**的地方——关系来自模型的世界知识，可能过期也可能记错。所以：

- 每条关系一律标为「待证实」，不会伪装成已核实的事实；
- 每条必须写明**该去哪份公开文件的哪一节核对**（年报某章节、招股书、行业协会数据）；
- 提示词禁止它给市场份额、销售占比这类具体数字——记忆里的数字最容易过期；
- 没确认的关系不进入任何公司的时间线，也不参与行业对照。核对过再点「标为已证实」。

## 研究报告

按公司已归档的证据生成简报，四节：这家公司在做什么 / 最近发生了什么变化 / 这些变化指向什么 / 还没有答案的问题。

**每个陈述都带来源编号**，编号对应到具体那条证据。提示词锁死：只能用给出的编号资料，不许补充任何模型自身知识；
没有编号支撑的句子不许写；资料没覆盖的写进「档案里还没有答案的」。没有归档证据时直接报错，不产出空洞简报。

报告按版本保存，可以对照不同时点自己的认知变化。

## 偏好设置

只影响显示，不影响任何研究结论与数据。设置存在浏览器的 localStorage 里，不进数据库、也不会被备份带走。

**四套主题**（只改颜色，不改布局）：纸感（默认）／高对比／暖光护眼／夜间。

**可读性的三个系统性问题已经在默认主题里修掉**：

| 问题 | 之前 | 现在 |
|---|---|---|
| 字号下限 | 86 处 8px、76 处 9px（234/320 的字号在 11px 以下），等宽字体在 8px 下几乎不可读 | 下限抬到 10px，并可整体缩放 |
| 次要文字对比度 | `#8b9aa0` 用了 50 次，在纸色上只有 2.6:1（WCAG AA 要求 4.5:1） | 提到 4.7:1 |
| 页面底纹 | 全页 28px 方格网格，长时间阅读时是持续的视觉噪声 | 可关闭 |

**字号缩放**分标准／大／特大三档，整体等比缩放，不改版式。

实现上把 87 个中性蓝灰与 20 个浅色边框收进了 CSS 变量，主题只改变量。**语义色不动**——涨跌红绿、
提示琥珀共 15 个保持硬编码，因为它们携带含义，跟着主题反转会丢掉信息。判断标准用的是绝对色度
而不是 HLS 饱和度：饱和度在暗色区会虚高，会把深蓝灰误判成语义色。

## 挂载到虾米伙伴（本地验证）

线上是单域名 + 路径分流，本机默认各跑各的端口——这个差异只有部署后才会暴露，
而暴露方式通常是「点进去一片空白」。`scripts/local-gateway.py` 把线上 Caddy 的规则原样搬到本机，
让「从虾米伙伴点进虾米看股」这条链路在推服务器之前就能走一遍。

```bash
# 1. 两边都按生产参数构建
VITE_BASE=/stocks/ npm run build
cd ../xiamimate-tools-frontend && NEXT_PUBLIC_API_BASE="" NEXT_PUBLIC_AI_ENABLED=1 npm run build && cd -

# 2. 后端照常跑在 8108
uvicorn stock_decision.main:app --reload --app-dir apps/api --port 8108

# 3. 起本地网关，规则与 deploy/caddy-snippet.conf 一一对应
python3 scripts/local-gateway.py --stocks apps/web/dist --main ../xiamimate-tools-frontend/out
# → http://127.0.0.1:8090/ 是可选的隔离网关验证入口；日常从主站
#   http://127.0.0.1:3000/stocks 进入，不要把 5217 当作用户入口。
```

**接口前缀不能用 `/api`**：线上 `/api/*` 已被主站的 AI 闸口占用（Caddy 转 8200）。
入口用 `handle_path /stocks-api/*` 剥掉前缀再转发到 8108，后端看到的仍是 `/api/v1/...`，一行不用改。

前端靠**挂载路径**而不是主机名判断部署形态（`apps/web/src/config.ts`）——
用主机名会把「在本机跑生产形态」误判成开发环境，接口打到主站后端去，页面就是白的。

## 上线之前跑什么

```bash
bash scripts/release-check.sh        # 门禁：两个数据库各跑一遍测试、前端、构建+首屏预算、依赖漏洞
                                     # --fast 可跳过 SQLite 那一遍（赶时间时才用）

# 部署形态的冒烟：真实的 /stocks/ 路径 + 真实浏览器
PLAYWRIGHT_PATH=<某处的 playwright/index.mjs> node scripts/smoke.mjs --base http://127.0.0.1:8092

ssh <your-server> 'bash /srv/<your-app>/deploy/deploy.sh'
```

**为什么冒烟单独一支。** 单元测试再厚也绕不过两样东西：部署形态（挂在 `/stocks/`
子路径下、接口前缀是 `/stocks-api`）和浏览器。已经因此漏过两次——三个下载链接
裸写 `/api/…`（测试只看 `fetch(`），以及熔断抛的 `CreditsError` 被接口层的
`except RuntimeError` 改写成 503（单测直接调 `llm.reserve()`，走不到那一层）。

`scripts/smoke.mjs` 里写死了一条铁律：**找不到目标 = 失败，不是跳过**。
第一版把"页面上没有可删的策略"写成跳过，于是整支脚本打了绿色的 ✓，
而真正要验的那一步一次都没跑。

## 服务器上跑在哪个账号下

`deploy/harden-service.sh` 一次性把后端从 root 降到 `xiamimate` 系统账号
（幂等、可重复跑）。**改 unit 里的 `User=` 之前必须先跑它**：用户不存在时
systemd 直接拒绝启动，那是一次实打实的停服。回滚写在脚本顶部。
